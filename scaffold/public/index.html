End-user Dashboard Designer
The editor your users get inside Concert Operate: they add widgets and your dashboards, bind them to live alert and incident data, drag and resize, link widgets so a click filters the others, and save or export the result. Layouts you make in Design use the same widgets, and one can be made the starting layout for every user.
Installing copies the Designer into dashboards/dashboard-builder/ and the build folder, registers its panel in src/index.js and adds the /dashboard-builder route. Then use Build & Deploy and hard-refresh Concert Operate (Cmd+Shift+R). Dashboards people save live in their own browser; they can export and import JSON files.
Git: dashboard versions
Design > Versions commits, pushes and pulls your dashboards with your own git login, and brings back older versions. Only dashboard files are committed (dashboards/layouts, the published copies and their sidebar entries), never code. No force push, rebase or branch switching: do those in a terminal.
Real data for Design
Design shows sample data until you load a data snapshot of your tenant. To make one, in Concert Operate open the Dashboard Designer, then ⋮ › Check the Concert Operate API › Record and download, and upload the file here. Design then shows your real alerts, incidents, applications and policies, as they were when the snapshot was taken. Nothing is ever sent to Concert Operate. The file holds real data: it is kept in .studio/ on this computer, which git ignores.
Topology proxy
Lets dashboards in Concert Operate read the ASM topology service (Raw JSON tab, real neighbours). The service has its own address and login, so Studio holds them and forwards read-only requests. The password stays in .studio/topology.json on this computer and is never sent to a page.
Split dashboards into tiles
Design can only place a dashboard's sections as separate tiles if the dashboard supports a part option. Make splittable adds that to a hand-written dashboard: Studio reads its source, cuts the top-level layout into sections (named after the comments above them), keeps one shared live instance, and backs the file up first. Undo restores the backup. Deploy afterwards.
