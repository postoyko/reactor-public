3D force graph panel

Explore open alerts as a three-dimensional network, drawn by your graphics processor (GPU), and use any node to filter the alert list.

Concept

About the 3D force graph

The 3D force graph is a custom panel for the dashboard extension toolkit. It draws your open alerts as a network of nodes and links in three dimensions. A physics simulation pulls related items together and pushes unrelated items apart, so resources that share an alert source, a team, or an alert type form visible clusters.

Use the graph to answer questions that a flat list cannot answer quickly:

  • Which alert sources or teams are connected to the most affected resources?
  • Do several critical resources share one source, which suggests a common cause?
  • Which resources are isolated, and which sit at the center of a cluster?

The graph is drawn with WebGL, which uses the GPU of the computer that runs your browser. Nothing is rendered on the server.

NoteThe panel reads the same alert data as the other toolkit example panels. It does not change alerts. The only thing it changes is the filter that is applied to the alert list on the same page.

Concept

What the graph shows

The graph has two kinds of nodes.

Resource nodes
One node for each resource name in your open alerts. The node color is the highest severity of the alerts on that resource. The node size grows with the number of open alerts on the resource.
Group nodes
One node for each distinct value of the dimensions you choose in Group by: alert source, team, or alert type. A group node is larger when more resources are linked to it. Group nodes have their own colors, so you can tell them apart from resource nodes.

A link joins a resource to each group node that it shares. When you point at or select a node, particles can travel along its links to make its connections easier to follow (see the Flow control).

A selected node is drawn in white. Items that are not related to the node you point at or select are dimmed.

Reference

Requirements

To view the graph

  • A current desktop browser with WebGL enabled. WebGL 2 is used when available, and WebGL 1 is used otherwise.
  • Hardware graphics acceleration turned on in the browser. Without it the panel falls back to a ranked list (see Messages and states).
  • A pointing device. The 3D canvas is operated with the mouse or a trackpad.

To install the panel

  • A Cloud Pak for AIOps cluster with the dashboard extension feature enabled.
  • Node.js v18 and the OpenShift CLI (oc) on the computer that you deploy from.
  • An API key for your user, and cluster-administrator access for the one-time enablement step.
  • A fork of the toolkit that contains this panel. The upstream toolkit repository is archived and read-only, so you cannot add the panel to it.
Task

Installing the panel

You install the panel the same way as the other toolkit examples: build the bundle, upload it, and register the routes.

Before you begin
  • Apply the 3D force graph changes to your fork of the toolkit.
  • Create an API key from your profile page in the console (/zen/#/settings/profile/list).
  • Find the namespace where Cloud Pak for AIOps is installed.
Procedure
  1. Install the dependencies, including the three new graph libraries. 
    npm install
    Run this in your fork so that package-lock.json is regenerated for the new dependencies.
  2. Log in to the cluster as an administrator. 
    oc login --token=<admin user token> --server=<your cluster>
  3. Enable the dashboard extension feature. You do this once for each cluster. 
    npm run enable -- -n <AIOps namespace>
  4. Open target.json and set the console URL, your user name, your API key, your tenant ID, and the bundle name.
  5. Build, upload, and register the example dashboards. 
    npm run deploy -- -n <AIOps namespace>
  6. Wait a few minutes, then log out of the console and log in again to refresh the menus.
Results

The Alerts 3D force graph and 3D force graph (full page) entries are added under Example dashboards.

ImportantThe alert query in the toolkit samples uses the toolkit's own sample tenant ID. Replace it with the tenant ID of your cluster before you expect to see your alerts, as you would for the other example panels.

What to do next

Open the panel.

Task

Opening the panel

  1. Log in to the console.
  2. In the navigation menu, expand Example dashboards.
  3. Click one of the two entries:
    • Alerts 3D force graph shows the graph in the upper part of the page and the alert list below it. Use this page when you want clicks in the graph to filter the list.
    • 3D force graph (full page) gives the whole page to the graph. It has no alert list.

On first load, a placeholder shows while alerts are retrieved. The graph then settles for a few seconds as the layout is calculated.

Task

Exploring the graph

  1. Rotate the view by dragging the background with the primary mouse button.
  2. Zoom with the scroll wheel or a trackpad pinch.
  3. Pan by dragging the background with the secondary mouse button.
  4. Point at a node to see a tooltip with its name, its type, and the number of open alerts (with the highest severity) for a resource or the number of linked resources for a group. The node and its direct neighbors stay bright and everything else is dimmed.
  5. Drag a node to move it. Dragging is available for graphs of fewer than 4,000 nodes.
  6. Click Fit view to bring the whole graph back into view.

NoteMoved nodes keep their positions when the data refreshes. Only new nodes are placed by the layout.

Task

Filtering the graph

Use the controls above the graph to reduce what is drawn. The status line under the controls updates to match.

  1. To change how resources are connected, open Group by and select one or more of Alert source, Team, and Alert type. If you clear every choice, the default of Alert source and Alert type is restored.
  2. To hide lower-severity alerts, choose a value in the severity list, for example Major and above. Resources whose alerts are all below the chosen severity disappear.
  3. To find a resource, type in Search resources. The search is not case-sensitive and matches resource names and the alert source, team, or alert type values of the dimensions selected in Group by.

If your filters hide the selected node, the selection is cleared and the alert list is released at the same time.

Task

Filtering the alert list from the graph

Before you begin

Open Alerts 3D force graph. The full-page route has no alert list to filter.

Procedure
  1. Click a node in the graph.
  2. Read the Selected node card at the upper right. It shows the node name and type, its alert or resource count, and its number of direct connections.
  3. Look at the alert list below the graph. It is filtered to the alerts that the node represents:
    • For a resource node, the alerts on that resource.
    • For a group node, the alerts that have that alert source, team, or alert type.
  4. To remove the filter, click the same node again, click the empty background of the graph, or click Clear selection.

NoteThe panel sets the alert list filter through the page address, the same mechanism that the Top N example panels use.

Task

Configuring a route

Defaults for grouping, graph size, and refresh are set in the route's state in config/routes.json. Users can still change grouping, severity, and search in the page; those choices are not saved between visits.

  1. Open config/routes.json and find the route for the graph, /alerts-force-graph-3d.
  2. In the graph region's state, edit linkBy, maxNodes, or refreshSeconds. See Route properties for the values.
  3. Run npm run deploy -- -n <AIOps namespace> again.
  4. Log out of the console and log in again.

To use the graph on another page, give a region of any route the same bundle path as the existing graph route and the panel ID force-graph-3d. To give the graph the whole page, set the bundle path and panel ID at the root of the route, as the /force-graph-3d route does, instead of inside a region.

Task

Removing the panel

To remove only this panel, delete its two routes and the two menu entries from config/routes.json, then run npm run deploy -- -n <AIOps namespace>.

Importantnpm run remove deletes the AIOpsUIExtension custom resource that registers all of the example dashboards, not only this panel. Use it only when you want all of them removed.

Route properties

Set these in the state object of the graph region.

Properties of the 3D force graph panel
PropertyTypeDefaultDescription
linkByArray of strings, or a comma-separated string["sender.name", "type.classification"]The group dimensions that are selected when the page opens. Valid values are sender.name (alert source), team, and type.classification (alert type). Other values are ignored. If none are valid, the default is used.
maxNodesPositive number1500The most resource nodes to draw. When there are more, the most severe resources are kept first, then the resources with the most alerts. Values that are not positive numbers fall back to the default.
refreshSecondsNumber0How often to reload the alerts, in seconds. Zero or less turns timed reloading off.

Regardless of this setting, the graph reloads when the console asks all panels to refresh alerts. Only requests that come from the console's own address are accepted.

Reference

Performance and GPU behavior

The panel adjusts its drawing detail to the size of the graph so that large estates stay responsive on laptops with integrated graphics. The tier is chosen from the number of nodes plus half the number of links.

Quality tiers
TierLoadNode detailFlow particles
High1,500 or fewerSmooth spheresAvailable
BalancedMore than 1,500ReducedNot available
PerformanceMore than 6,000Lowest, and a shorter layout runNot available
  • When the tier does not allow particles, the Flow switch has no visible effect.
  • Edge smoothing (antialiasing) is turned off for graphs of 4,000 or more nodes, and node dragging is turned off at the same size.
  • The display resolution is capped at twice the standard pixel density, even on very dense screens.
  • Drawing stops while the browser tab is in the background and resumes when you return.
  • The high-performance GPU is requested when the computer has more than one. The browser can still choose differently.

GPU context loss

Drivers, sleep and wake, and browser memory pressure can take the GPU away from a page. When this happens the panel shows a warning, waits for the browser to give the GPU back, and then rebuilds the graph from scratch. Node positions are kept in memory, so the layout looks the same afterward.

Troubleshooting

Troubleshooting

The menu entries do not appear

Wait a few minutes after deployment, then log out and log in again. Confirm that the deployment finished without errors and that the routes were added under Example dashboards.

The panel is blank or shows Unable to load alerts

Check that your tenant ID is correct and that your user can read alerts. Open the browser developer tools and look at the failed request to see the status code and response.

The panel shows 3D view unavailable

Turn on hardware acceleration in the browser settings and restart the browser. Remote desktop sessions and some virtual machines have no GPU, so use the ranked list there.

The graph is slow or the fans spin up

  • Lower maxNodes in the route, or raise the severity filter.
  • Switch Layout to Frozen once the shape is settled.
  • Switch Flow off.
  • On a computer with two GPUs, make sure the browser runs on the high-performance one.

Some resources are missing

Check the status line for a count of hidden lower-priority resources. Raise maxNodes or filter by severity or search to bring them in. Alerts with no resource name are never drawn.

Clicking a node does not change the alert list

You are probably on the full-page route, which has no list. Open Alerts 3D force graph. If the list is present but does not change, check that the page was not opened with a fixed filter.

The alert list is empty after clicking a node whose name contains a quote

The panel escapes single quotes by doubling them. If your cluster uses a different escape rule, the filter can be wrong for those names. Click Clear selection and report the name pattern to the person who maintains your fork.

The graph went black

This is usually a GPU context loss. Wait for the recovery message to clear. If it does not, reload the page.

Reference

Limitations

RestrictionThe 3D canvas is operated with a pointer. It has no keyboard navigation. The controls above the graph are keyboard accessible, and the ranked list that appears when WebGL is unavailable is a standard table.

  • The graph shows open alerts only and one resource name for each resource node.
  • Grouping, severity, and search choices are not remembered between visits. Use route properties for the defaults.
  • Graphs with more resources than maxNodes are cut to that limit. Raising it is possible, but large graphs are slower to lay out and draw.
  • The panel was built and unit-tested without a GPU. Draw performance, frame rates, and GPU recovery should be checked in the browsers and on the hardware that your users have before wide rollout.
  • The upstream toolkit is archived. Updates to the panel and its libraries are the responsibility of the team that owns your fork.
